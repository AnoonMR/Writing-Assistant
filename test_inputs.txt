Activity 2 — Sample Inputs & Expected Outputs for Live Demo
=============================================================
These were generated by actually running the current code (not guessed),
so they are safe to use live in the demo / viva. Run the app with:

    cd a2/src
    python app.py

then open http://127.0.0.1:5000 and type the inputs below.


PART 1 — Spell correction only (type a single misspelled word)
----------------------------------------------------------------
Input        Expected correction
----------------------------------------------------------------
teh          the
recieve      receive
langauge     language
wrok         work
wht          what
ovr          over
the          the            (already correct -> unchanged)

Known quirk (worth mentioning in the demo / Error Analysis, NOT a bug to
hide): "helo" currently corrects to "here", not "hello". Both are real
edit-distance-1/2 neighbours of "helo"; "here" wins because it's a much
more frequent word in the Brown Corpus and the learned confusion-matrix
probability for that specific edit is higher. Good talking point for
"why is this different from a dictionary spell-checker".

Notes for the demo
----------------------------------------------------------------
- Every "Corrected text" line above is what should appear under the
  "Corrected text" heading in the UI. The "Spelling fixes" words are
  the ones that should show a strikethrough original -> highlighted
  fix in the "Word-by-word analysis" section.
- All examples above use "trigram context" (the last two words), which
  the app will note under the suggestions as "Using trigram context
  (last two words)." If you type a single word instead, it'll say
  "Using bigram context" instead.
- These numbers/outputs were captured on 2026-10-11 by running the
  actual trained models (src/app.py's analyze() function), using the
  same data files committed in a2/data/. They should reproduce exactly
  if the data files aren't changed.
